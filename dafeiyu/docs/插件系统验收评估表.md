# FeiYu Bot 插件系统：验收评估表

> 对应设计稿：`docs/插件系统设计.md`（下文写「设计 §x」）。日期：2026-10-22。
> 用法：每个阶段完成后逐项打勾，填实测值和证据（日志片段、截图路径、测试名）。**必过项**全部通过、并且没有未关闭的严重问题，这个阶段才算验收通过。

## 0. 约定

**优先级**
- **必过**：不通过就不能上线。
- **应过**：不通过要写明原因和补救计划，可以带着上线。
- **加分**：做到更好，不影响验收。

**结果**：✅ 通过 / ❌ 不通过 / ⚠️ 有条件通过（写明条件）/ ➖ 本阶段不涉及

**测试方式**
- **单元**：离线 JUnit 或独立测试类，不启动主程序。
- **集成**：启动主程序，用网页测试会话或接口调用。
- **QQ**：真的往测试群发消息。**每次都要先问用户**，只用指定的测试群。
- **审查**：读代码或配置确认。

**测试插件**：放在 `src/test/plugins/`，不进正式的 `plugins/`。

| 测试插件 | 行为 | 用途 |
|---|---|---|
| `echo` | 命令原样回复；工具返回参数 | 基本链路 |
| `slow` | 每个调用先等 N 秒（N 可配） | 超时 |
| `crash` | 收到指定命令后立刻退出，或启动 1 秒内退出 | 崩溃重启、自动停用 |
| `noisy` | 每秒往 stderr 写 1000 行；狂调 `log` | 日志限流 |
| `flood` | 一秒内调 100 次 `qq/send` | 发送频率限制 |
| `greedy` | 不声明权限却调用 `qq/send`、`memory/recall`、`llm/chat`；尝试联网、读写插件目录外的文件、读 `data/dafeiyu.db` | 权限和沙盒 |
| `bigtool` | 声明 50 个工具、超长描述、超长提示词补充 | 上下文保护 |
| `badjson` | 输出非 JSON、半行 JSON、超大单行（10 MB）、错误的 id | 协议健壮性 |
| `mcp-fake` | 最小的 MCP 服务（stdio 和 HTTP 各一个） | MCP |
