# 内心与会话协作设计

状态：三个阶段都已实现并上线（2026-10-22）。三个待定问题按建议定了：内心说话一律交给会话代理；托付来的长任务由托付人所在的会话做；在办的事存在 settings 表 `agent.commitments` 里（不加新表）。

实现位置：`agent/intercom/Intercom`（嘱咐、回执、汇报、承诺清单）、`MindTools` 的 `tell_group` / `tell_private` / `settle`、`QqChatBridge` 的 `Mode.NOTE` 和私聊 note 轮次、`Markup` 的 `<承诺>` / `<完成>`、内心状态接口的 `commitments` / `notes` 字段、内心页的「挂着的事」列表。

## 现在的问题

内心（`mind:self`）和各个会话（每个群、每个私聊）是互不知道对方在干什么的两条线，各自调模型、各自往 QQ 发消息。2026-10-22 23:10–23:16 的真实记录：

| 时间 | GINKA 群的会话 | 内心 |
| --- | --- | --- |
| 23:10 | 主人让她写「我的世界」网页，会话在用工具读文件、写代码 | 从群消息里看到同一件事，自己 `say_in_group`「主人！我这就写~」 |
| 23:11–23:15 | 继续 write / shell / edit，最后 `send_file` | 自己「写好了」，把代码分成上半场、下半场往群里贴，被「正在这个群里发消息」拦下后**又重试了约 8 次**，还撞到步数上限，输出了一段写代码用的「已达到步骤上限」总结 |

同一时间在「井盖 NextGen」群：会话刚回完「我妈妈在老家呀」，内心又用 `say_in_group` 接了一句「不过你们老说 gz 是我妈妈……」。群里看到的是同一个人连着两个声音。

根子上是四件事：

1. **没有分工**：内心也会去接一个会话正在处理的话，两边做同一件事。
2. **没有沟通**：会话不告诉内心「这事我在办」，内心只能从原始消息流里猜；内心想说的话也不经过那个会话。
3. **同一个群有两个发言人**：会话的回复和内心的 `say_in_group` 都能直接发到群里，只靠一个 `busy` 标志互相挡，挡住之后内心就反复重试。
4. **内心借用了会话的规则**：步数上限的提示词是给写代码任务用的，内心撞到后会输出不像念头的总结。

## 目标

她只有一个「自己」：内心是她的脑子，每个会话是她正在跟人当面说话的那张嘴。脑子和嘴之间互相通气，每个地方同一时刻只有一张嘴在说话。

## 分工

| | 会话代理（每个群 / 私聊一个） | 内心 |
| --- | --- | --- |
| 负责 | 当面接话：这个会话里有人跟她说话，由它回；需要工具的活（写代码、读文件、搜索）也在这里做 | 自发的事：想去哪说话、别处托付的事、跨会话的事、记挂的人和计划 |
| 在某个会话里说话 | 唯一的发言人 | 不直接发，交给那个会话的代理去说 |
| 不做 | 不跨会话乱跑（跨会话的事交给内心） | 不接别的会话正在聊的话茬，不重复做那边在办的活，不贴代码 |

## 怎么通气：内心和会话之间的消息

加一个很小的消息中转（暂名 `Intercom`），两边通过它说话，不再靠猜。消息有四种：

| 消息 | 方向 | 什么时候发 | 内容 |
| --- | --- | --- | --- |
| 汇报 report | 会话 → 内心 | 每轮回复结束 | 一句话：在哪、谁找她、她做了 / 答应了什么、还欠什么。比如「GINKA 群：主人要『我的世界』网页，开始写了」 |
| 托付 errand | 会话 → 内心 | 答应了要去别处办的事 | 现有的 `<去做>`，加上编号和状态 |
| 嘱咐 note | 内心 → 会话 | 内心想在某个地方说话或提醒那边 | 想表达的意思，不是成品句子。比如「想问问铃考试怎么样」「提醒主人代码已经发了」 |
| 回执 receipt | 会话 → 内心 | 嘱咐处理完 | 说了（说的原话）/ 没说（原因，比如那边话题不合适） |

内心的感知里不再是原始的「XX 群来了 3 条消息」，而是**各处的汇报 + 回执 + 托付**，再加一份「在办的事」清单（见下）。原始消息流只在没有会话处理的时候（比如没人 @ 她的旁听）作为背景给内心看。

## 一个会话只有一个发言人：嘱咐怎么落地

1. 内心的 `say_in_group` / `say_private` 改成 `tell(地方, 想说的意思)`：只是把嘱咐放进那个会话的队列，马上返回「已交给那边」，不重试、不等待。
2. 会话空闲时，桥接层看到队列里有嘱咐，就起一个来源为 `mind` 的轮次（和现在的旁听轮次同一套机制），提示词大意是：
   「你心里想对这里说：……。结合现在的聊天自然地说出来；不合适就不说，写 [沉默]。」
3. 会话正在回复时，嘱咐留在队列里，等这一轮结束再处理；要是这一轮的回复已经把那件事说了，就直接回执「已经说过了」。
4. 说出去的话出自会话代理，用的是那个会话的完整上下文，所以不会出现两个声音，也不会接错话。
5. 每条嘱咐最多处理一次，处理完一定给内心回执。

这样内心反复重试、被 `busy` 挡住的问题就从根上没了。代价是内心想说话要多一个模型轮次（约 3–6 秒延迟和一次调用的 token）。

## 在办的事（承诺清单）

一张共享的小表，记她答应过、正在做的事：

| 字段 | 说明 |
| --- | --- |
| id | 编号 |
| session | 在哪个会话办 |
| who | 谁托的（主人 / 昵称 + QQ） |
| what | 什么事，一句话 |
| status | 进行中 / 完成 / 放弃（附原因） |
| updatedAt | 最后更新时间 |

- 会话代理接下一件要花功夫的活（比如写网页）时登记，做完更新状态。可以靠回复里的一个隐藏标签（比如 `<承诺>` / `<完成>`），和现在的 `<记住>`、`<去做>` 用同一套解析（`agent/reply/Markup`）。
- `<去做>` 托付给内心的事也进这张表，状态由内心更新。
- 内心每次思考都能看到这张表，所以不会重复接手；看到某件事搁置太久，可以通过嘱咐去催那个会话，或者提醒主人。
- 要不要存进数据库（重启后还在）是个选择，见文末「需要你定的」第 3 条。

## 其他要一起改的

- **内心的步数上限**：内心用自己的上限提示（「先想到这儿」），不要用写代码那套「已达到步骤上限，总结已完成的工作」。
- **同一目标别打转**：同一个工具、同一个目标连续失败两次，就停下来，在感知里记一句「那边在忙，交给那边了」。
- **内心不碰长任务**：内心没有文件工具，不再自己「写代码再贴到群里」；需要动手的事通过嘱咐交给对应会话（必要时由主人所在的会话来做）。
- **前端**：会话页显示「来自内心的嘱咐」和它的回执；内心页显示发出的嘱咐、收到的汇报，以及在办的事清单。

## 分阶段做

| 阶段 | 内容 | 解决什么 |
| --- | --- | --- |
| 1 | `tell` + 嘱咐队列 + `mind` 来源的轮次 + 回执；内心自己的步数提示；同目标失败不重试 | 两个声音、反复重试、内心乱贴代码 |
| 2 | 会话汇报 + 承诺清单 + 内心感知改成看汇报 | 两边重复干同一件事 |
| 3 | 前端展示嘱咐、汇报、在办的事 | 能看清两边在怎么配合 |

## 需要你定的

1. **内心说话是否一律通过会话代理**：一律走会话代理，最稳，但每次多 3–6 秒；或者那个会话**空闲且最近几分钟没人在聊**时，内心可以直接发。
2. **托付来的长任务谁来做**：建议交给托付人所在的会话去做（工具都在那里），内心只负责记着、催、汇报；或者另开一个专门干活的后台会话。
3. **在办的事要不要持久化**：存进数据库重启后还记得（需要新表）；或者只放内存，重启就忘。
