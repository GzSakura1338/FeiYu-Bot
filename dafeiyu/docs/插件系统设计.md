# FeiYu Bot 插件系统：设计与计划（草案）

> 状态：设计稿，未开工。日期：2026-10-22。
> 目标：不改主程序代码，就能给她加各种自定义功能。插件可以用任何语言写，坏了不影响主程序，装别人的插件也不用担心它乱来。

## 1. 插件能做什么（举例）

| 想要的功能 | 用到的扩展点 |
|---|---|
| 群里发“#今日人品”直接回一个结果，不经过大模型 | 命令 |
| 每天早上 8 点给某个群发天气和早报 | 定时任务 + 发消息 |
| 给她一个“查天气”“查快递”“查 Steam 价格”的工具，聊天时自己调用 | 工具 |
| 有人进群自动欢迎、有人撤回消息时吐槽一句 | 事件订阅 |
| 群里有人发 B 站或 GitHub 链接时，自动附上一段解析 | 事件订阅 + 发消息 |
| 敏感群里发出去的话再加一道自定义审核，或者全部翻译成英文 | 出站过滤 |
| 每次聊天时告诉她“今天是某某的生日”“现在服务器在线人数” | 提示词补充 |
| 接入现成的 MCP 服务（文件系统、数据库、GitHub、地图……） | MCP |

## 2. 三种插件

| 类型 | 写法 | 能做的 | 适合 |
|---|---|---|---|
| **MCP 服务** | 不用写代码，填启动命令或网址 | 只提供工具 | 直接用社区里现成的几千个 MCP 服务 |
| **FeiYu 插件** | 任何语言写的独立程序，通过标准输入输出说 JSON-RPC；提供 Python 和 Node 的 SDK | 本文档的所有扩展点 | 自定义功能的主力 |
| **技能包** | 一个或多个 `SKILL.md` | 只是知识和做法，进技能库 | 教她“遇到某类事怎么做”，已有技能系统，直接导入 |

**不做 Java JAR 插件（在主程序里直接加载）。** 原因：
- 它和主程序在同一个进程里，一个插件死循环或崩溃会拖垮整个机器人。
- 没法把它关进沙盒。
- 必须用 Java 写还要编译，门槛高。

独立进程多出的开销是每次调用 1～5 毫秒，可以忽略。

## 3. 插件长什么样

一个插件就是 `plugins/` 下的一个文件夹：

```
plugins/
  jrrp/                        # 文件夹名 = 插件 id
    plugin.json                # 清单
    main.py                    # 代码（任何语言）
    README.md                  # 可选，网页上显示
    icon.png                   # 可选
```

`plugin.json`：

```json
{
  "id": "jrrp",
  "name": "今日人品",
  "version": "1.0.0",
  "author": "someone",
  "description": "群里发 #今日人品 回一个 0～100 的数，每人每天固定",
  "host": ">=0.2.0",
  "run": { "command": "python", "args": ["main.py"] },
  "permissions": ["qq.reply"],
  "commands": [
    { "name": "今日人品", "aliases": ["jrrp"], "description": "看看今天的人品", "scope": ["group", "private"] }
  ],
  "events": [],
  "tools": [],
  "schedules": [],
  "settings": {
    "type": "object",
    "properties": {
      "lucky_text": { "type": "string", "title": "满分时的话", "default": "今天无敌了！" }
    }
  }
}
```

- `tools` 也可以留空，由插件启动后动态上报（`tools/list`），和 MCP 一样。
- `settings` 用 JSON Schema 写。网页根据它自动生成设置表单，不用写前端。字段标 `"secret": true` 的（比如 API Key），会加密存储，并且不在页面上回显。

## 4. 扩展点

### 4.1 命令

- QQ 里以命令前缀开头的消息（默认 `#`，可在设置里改），会先交给声明了这个命令的插件。插件直接回复，**不经过大模型**，又快又省钱。
- 插件返回 `{handled: true}` 时，这条消息就结束了，她不会再回一遍。返回 `false` 时，照常交给她。
- 网页控制台的 `/` 命令也可以由插件提供。比如 `/rss list`。

### 4.2 工具

- 插件声明的工具会和内置工具一起出现在「工作目录」的工具列表里，可以单独开关。
- 名字自动加前缀：`plugin__jrrp__roll`、`mcp__github__search_issues`。
- 可以声明 `"mind": true`，表示内心也能用这个工具。
- 调用超时默认 60 秒，可以在清单里调整，最多 10 分钟。
- 工具描述会进系统提示词，所以清单里限制在 1000 字以内，防止一个插件把上下文撑爆。

### 4.3 事件订阅

可以订阅的事件：

| 事件 | 内容 |
|---|---|
| `message.group` / `message.private` | 收到的消息（已解析成文字 + 附件列表 + 是否 @ 了她） |
| `notice.poke` / `notice.join` / `notice.leave` / `notice.recall` | 拍一拍、进群、退群、撤回 |
| `bot.said` | 她发出去的话（群、私聊、内容） |
| `bot.thought` | 内心的念头（需要 `mind.read` 权限） |
| `bot.connected` / `bot.disconnected` | NapCat 连上和断开 |

收到的消息事件分两种用法：

- **旁听**（默认）：异步通知，插件慢了也不耽误她回复。
- **拦截**（清单里写 `"intercept": true`）：她回复之前先同步问插件。插件可以返回：
  - 放行
  - 吞掉（她不回）
  - 改写（比如把消息里的短链接展开）
  
  每个插件最多等 2 秒，超时按放行处理。多个插件按优先级排队。

### 4.4 定时任务

```json
"schedules": [{ "id": "morning", "cron": "0 8 * * *", "description": "早报" }]
```

时间到了，宿主会发 `schedule.fire` 给插件，插件再调用发消息的接口。半夜（1～8 点）不受“她睡了”的限制，因为这是插件的事，不是她的事。

### 4.5 提示词补充

插件可以提供一小段文字，宿主会放进每轮的 `<你记得>` 后面，标成 `<插件:天气>…</插件:天气>`。

- 每个插件最多 300 字。
- 每轮调用超时 500 毫秒，超时就跳过，不卡回复。

### 4.6 出站过滤

她要发出去的话，在内容审核之后、真正发送之前，可以交给插件过一遍。插件可以：
- 改写（比如繁简转换、翻译）
- 拦下（自定义审核）

这个扩展点需要 `qq.filter` 权限，每个插件最多等 2 秒。

### 4.7 网页

- **自动设置表单**：根据 `settings` 自动生成。
- **自定义页面（可选）**：插件提供 `web/index.html`，在「插件」页里用 iframe 打开，走 `/plugins/{id}/` 这个地址。页面里能调用的接口只有这个插件自己的。

## 5. 插件能调用宿主的哪些接口

插件通过同一条 JSON-RPC 通道调用宿主。每个接口都要在清单里声明权限，装插件时给你确认：

| 权限 | 接口 | 说明 |
|---|---|---|
| `qq.reply` | `qq/reply` | 只能回复触发它的那条消息（命令、事件），最常用、最安全 |
| `qq.send` | `qq/send`、`qq/groups` | 主动往群或私聊发消息。要再列出允许的群（在设置里勾选），并且走 `QqOutbox` 的内容审核和频率限制。`qq/groups` 返回勾选的群，插件不用再自己填群号 |
| `qq.read` | `qq/history`、`qq/groups`、`qq/members` | 读聊天记录、群列表、群成员 |
| `qq.filter` | 出站过滤 | 见 §4.6 |
| `memory.read` / `memory.write` | `memory/recall`、`memory/add` | 读写她的记忆（按现有的隐私可见规则） |
| `mind.read` | `bot.thought` 事件 | 看她的内心 |
| `llm` | `llm/chat` | 用当前的模型做一次对话（比如让插件自己写摘要）。token 记在 Token 用量页的「插件:id」名下，不限额度 |
| `network` | — | 插件进程能上网（沙盒默认断网） |
| `files` | — | 插件能读写工作目录（默认只能读写自己的数据目录） |

所有插件都能用的：
- `kv/get`、`kv/set`：自己的键值存储，在数据库里，按插件隔离。
- `log`：写日志，在网页上按插件查看。
- `notify`：在网页上弹一条提示。
- 自己的数据目录：`data/plugins/{id}/`。

## 6. 运行与隔离

- **进程**：每个启用的插件是一个子进程，宿主启动时拉起。宿主通过标准输入输出，用按行分隔的 JSON-RPC 2.0 和它对话。插件的 stderr 进日志。
- **沙盒（默认开）**：复用现有的 `AppContainerSandbox`。插件进程只能读写自己的文件夹和数据目录，CPU 和内存受限，默认断网。声明了 `network` 或 `files` 并且你同意后，才放开对应的能力。你自己写的、信得过的插件，可以在网页上对单个插件关掉沙盒。
- **健壮性**：
  - 插件崩了，自动重启，间隔从 1 秒逐步拉长到 5 分钟。
  - 10 分钟内崩 5 次，就停用并在网页上标红。
  - 任何调用超时，都不会卡住她回复。
- **热更新**：网页上点「重新加载」，或者插件文件夹里的文件变了（开发模式），就重启这个插件进程，不用重启主程序。
- **宿主停止时**：发 `shutdown`，等 3 秒，再强制结束。

## 7. MCP 支持

- 宿主是 MCP 客户端，支持两种传输：
  - **stdio**：填启动命令、参数和环境变量，比如 `npx -y @modelcontextprotocol/server-github`。
  - **Streamable HTTP**：填网址和请求头。
- 连上后用 `tools/list` 拿到工具，接进工具列表，名字是 `mcp__{服务名}__{工具名}`。
- 和插件一样可以：单个开关、设置超时、关进沙盒（stdio 类型）、设置“QQ 里谁可以用”。
- 第一版只接 `tools`，`resources` 和 `prompts` 以后再说。

## 8. 安装与管理

网页新增「插件」页，放在左侧栏，和智能体平级：

- **已安装**：卡片显示图标、名字、版本、作者、状态（运行中 / 已停止 / 出错）、启用开关。点进去能看：
  - 说明（README）
  - 权限
  - 设置表单
  - 命令、工具、定时任务
  - 日志
  - Token 用量
  - 「重新加载」「卸载」
- **安装**：
  - 上传 zip
  - 填 Git 仓库地址或 zip 网址（下载要经过你同意，下载后先显示清单和权限，确认后才启用）
  - 直接把文件夹放进 `plugins/` 后点「刷新」
- **MCP 服务**：单独一栏，添加、编辑、开关、看连接状态和工具列表。
- **技能包**：在「记忆 › 技能」里加「导入」按钮，支持 `SKILL.md` 或 zip。
- **插件市场（以后）**：维护一个公开的索引文件（GitHub 上的一个 JSON），页面上可以浏览和一键安装。安装流程和上面一样，要确认权限。

## 9. 宿主内部改动

```
plugin/
  PluginHost        扫描 plugins/、校验清单、拉起和重启进程、热更新
  PluginProcess     一个插件进程：JSON-RPC 收发、超时、沙盒
  PluginManifest    清单解析和校验（版本、权限、Schema）
  PluginApi         处理插件发来的调用，按权限放行
  PluginStore       启用状态、设置（DPAPI 加密 secret 字段）、kv、日志
  mcp/McpClient     MCP stdio / HTTP 客户端
```

接入现有代码的地方：

| 现有位置 | 改动 |
|---|---|
| `Toolbox`（静态工具表） | 改成 `ToolRegistry`：内置工具 + 插件工具 + MCP 工具。`TurnRunner` 和 `MindTools` 都从这里取 |
| `QqChatBridge.onEvent` | 解析后先过 `PluginHost.dispatch`（命令、拦截、旁听），再交给她 |
| `QqOutbox.deliver` | 审核后、发送前，过出站过滤 |
| `TurnRunner.request` | 每轮前缀里加插件的提示词补充 |
| `Mind` | 念头发出 `bot.thought` 事件 |
| `WebConsole` | 加 `/api/plugins/…`、`/plugins/{id}/`（插件页面）、`/api/mcp/…` |
| `UsageStore` | 用途多一类「插件:id」 |
| 数据库 | 库版本 +1：`plugin_kv`、`plugin_logs` 两张表；插件设置和启用状态放 settings |

## 10. SDK 与示例

- **Python SDK**：单个文件 `feiyu_plugin.py`，没有第三方依赖，用装饰器注册。

```python
from feiyu_plugin import Plugin
import hashlib, datetime

p = Plugin()

@p.command("今日人品")
def jrrp(ctx):
    seed = f"{ctx.user_id}{datetime.date.today()}".encode()
    score = int(hashlib.md5(seed).hexdigest(), 16) % 101
    text = p.settings["lucky_text"] if score == 100 else f"你今天的人品是 {score}"
    ctx.reply(text)

@p.tool("weather", "查某个城市现在的天气", {"city": {"type": "string"}})
def weather(city):
    ...

p.run()
```

- **Node SDK**：同样的接口，第二阶段再做。
- **示例插件**（放进仓库的 `plugins/examples/`，默认不启用）：
  1. 今日人品（命令）
  2. 天气（工具，要 `network`）
  3. 早报定时推送（定时任务 + `qq.send`）
  4. 进群欢迎（事件）
  5. 关键词自动回复（拦截）
  6. RSS 订阅推送（定时任务 + kv）
- **开发文档**：`docs/插件开发.md`，写清协议格式、每个方法的参数、权限表，并附上调试办法：开发模式下改了文件自动重载，日志实时显示在网页上。

## 11. 协议草案（JSON-RPC 2.0，每行一条）

宿主 → 插件：

| 方法 | 参数 | 返回 |
|---|---|---|
| `initialize` | `hostVersion, pluginId, settings, dataDir` | `{tools?, commands?}`（可以动态补充） |
| `command/run` | `name, args, text, session, userId, groupId?, messageId` | `{handled}` |
| `event` | `type, ...事件字段` | 旁听：无；拦截：`{action: pass/drop/rewrite, text?}` |
| `tool/call` | `name, arguments, session` | `{content, isError}` |
| `schedule/fire` | `id` | 无 |
| `prompt/contribute` | `session, people` | `{text}` |
| `filter/outgoing` | `session, text` | `{action: pass/drop/rewrite, text?}` |
| `settings/changed` | `settings` | 无 |
| `shutdown` | — | 无 |

插件 → 宿主：`qq/reply`、`qq/send`、`qq/history`、`qq/groups`、`memory/recall`、`memory/add`、`llm/chat`、`kv/get`、`kv/set`、`log`、`notify`。权限不够时返回错误码 `-32001`。

## 12. 分阶段计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1 宿主骨架** | `PluginHost`/`PluginProcess`/清单、JSON-RPC、命令和工具两个扩展点、`qq.reply`、kv、日志；Python SDK；网页「插件」页（列表、开关、日志、重新加载）；示例：今日人品、天气 | 群里发 `#今日人品` 由插件直接回；她聊天时会调用天气工具；插件崩溃自动重启，不影响她回复 |
| **P2 事件与定时** | 事件订阅（旁听 + 拦截）、定时任务、提示词补充、出站过滤、设置表单（含加密字段）、`qq.send`/`qq.read` | 进群欢迎、早报定时推送能跑；拦截插件超时不卡回复；设置改了插件立刻生效 |
| **P3 MCP** | MCP 客户端（stdio + HTTP）、网页 MCP 栏 | 接一个现成的 MCP 服务，她能在聊天里用它的工具 |
| **P4 沙盒与权限** | 插件进程进应用容器、按权限放开网络和文件、安装时确认权限、`llm`/`memory` 接口 | 没声明 `network` 的插件上不了网；越权调用被拒并记日志 |
| **P5 安装与分发** | zip / Git / 网址安装、版本兼容检查、技能包导入、Node SDK、插件自定义页面 | 从一个 Git 地址装上插件，确认权限后能用；卸载干净 |
| **P6 市场（可选）** | 公开索引、浏览、一键安装、更新提示 | 之后再定 |

每个阶段都先写离线测试（用一个假插件进程测协议、超时、崩溃重启），再在网页测试会话里试。涉及往 QQ 真发消息的测试先问你。

## 13. 风险

- **装了别人的插件 = 运行别人的代码。** 所以默认开沙盒、要声明权限、安装时你确认。来路不明的插件不要关沙盒。
- **工具太多会撑爆上下文、让她选错工具。** 插件工具默认对 QQ 会话关闭，在「工作目录」里手动打开；内心只给声明了 `mind: true` 的。以后工具超过 30 个时，再考虑只放名字、按需展开（同技能的做法）。
- **命令和她抢话。** 命令前缀默认 `#`，只有完全匹配到某个插件声明的命令才会被吞掉；没匹配上的照常交给她。
- **Python 环境。** 依赖你电脑上已装的 Python。沙盒里装不了包，所以插件要么只用标准库，要么把依赖放进自己的文件夹（`vendor/`），SDK 文档里写清楚。

## 14. 需要你拍板

1. **主力语言先做 Python，Node 放第二阶段？**
2. **沙盒默认开？** 建议开；你自己写的插件可以单独关。
3. **命令前缀用 `#` 还是 `/`？** `/` 在网页控制台已经被内置命令占了，QQ 里用 `#` 不容易冲突。
4. **要不要第一版就接 MCP？** 建议放在第三阶段。先把自己的插件协议做稳，MCP 的工具部分是它的子集，接起来很快。
5. **插件市场要不要做？** 要的话，索引放在哪个 GitHub 仓库？
