# FeiYu Bot

自己实现的 QQ 机器人控制台（代码里的包名和目录名仍叫 dafeiyu）（Java 25 + Gradle），前端按 m3.material.io 的 Material Design 3 风格设计。
负责连接 NapCat、记录消息，并用大模型在 QQ 里自动回复（Agent 部分对齐 opencode 的实现）。

## 运行

- 双击上一级目录的 `start-dafeiyu.bat`，或者在本目录执行 `.\gradlew.bat run`
- 打开网页控制台：http://127.0.0.1:8090/
- `config.properties`：控制台端口、前端目录、数据库位置，以及反向 WebSocket 的初始默认值
- 其余配置都在网页上管理，存在 SQLite 数据库 `data/dafeiyu.db`（含 API Key，已加入 .gitignore）；表结构升级前会自动备份到 `data/backup/dafeiyu-v<旧版本>-<时间>.db`

**改前端不用重启**：`web.dir`（默认 `src/main/resources/web`）存在时，后端每次请求都直接读这个目录，改完刷新浏览器即可。改 Java 代码需要重启。

**注释**：项目不写注释，改完运行 `python scripts/strip-comments.py`（`--check` 只检查）。

**NapCat 升级后**：在本目录运行 `node scripts/napcat-api.mjs`，从 `../napcat/napcat.mjs` 重新生成 QQ 接口清单 `src/main/resources/napcat-api.json`，再重启。

## Agent

- 网页「Agent」分六个子页：模型 / 人格 / 工作目录 / 会话 / 记忆 / 表情包（地址 `#agent/models`、`#agent/personas`、`#agent/workspace`、`#agent/sessions`、`#agent/memory`、`#agent/stickers`）；内心是会话列表里置顶的一项，旧的 `#agent/chat`、`#agent/mind` 跳到会话
- 会话：QQ 私聊、群聊和网页测试对话在同一个列表里，正在回复的实时显示生成过程、工具调用和她的「内心」；可以停止回复
  - QQ 会话：以控制台身份发消息（回复可选是否发到 QQ，消息带「【控制台】」标记）
  - 「新对话」建一个网页测试对话（`web:` 开头，重启后保留，标题取第一句话）：可以粘贴 / 拖入图片，头部切换人格和模型，发送的文件直接显示下载
- 命令（只在网页控制台可用，QQ 里发 / 开头的消息只是普通聊天）：`/clear` 清空上下文、`/compact` 立即压缩上下文、`/stop` 停止回复、`/status` 会话状态、`/say` 以机器人身份直接发到 QQ（不经过模型）、`/reflect` 立即回顾这个会话更新记忆、`/help`
- 主人：「人格」页填主人的 QQ 号后，主人的消息由程序加上「【主人】」标记；其他人消息和昵称里的【】会被换成普通括号，冒充不了
- 防认错人（群里）：
  - 一条群消息里的换行显示成「 / 」，伪造不出「花花：……」这样的假行；昵称里的冒号和换行也会去掉
  - 和别人重名、和主人重名、和机器人自己重名（唤醒词 / QQ 昵称）、名字里带「主人」的，昵称后面加「#QQ 尾号」区分；主人永远用原名
  - 群里出现和她重名的人或机器人时，每轮额外提醒「XX#1234 是和你重名的别人」；它 @ 她、回复她都不算叫她，只当普通群聊看心情接
  - 发出去的消息里 `#尾号` 会去掉，写「@昵称#尾号」会 @ 到对应的人
- 心情和内心：QQ 会话里模型每次回复先写一句 `<内心>…</内心>`（不发到 QQ，存在记录里，网页上显示成「内心」），程序把它当作她此刻的心情，下次回复时连同当前时间一起告诉她（「<你此刻>」），心情跨会话延续、随时间平复，24 小时后忘掉；Agent 页头显示她此刻的心情
- 记忆和自我总结（「记忆」子页，跟着人格走）：
  - 分区：关于她自己、日记、技能、主人、认识的每个人（按 QQ 号）、每个群
  - 日记一天一篇（`label` 是 `yyyy-MM-dd`，页面显示「2026年10月22日 星期四」）：回顾时把当天已写的日记和新聊天一起交给模型，重写成按时间顺序的完整一篇；新稿比旧稿短一半以上就当成补充接在后面，防止丢内容
  - 关于她自己按主题整理成几条：性格、喜好、习惯、经历、心愿和约定（经历和约定带日期）；聊天里当场记下的零散想法，下次回顾时并进主题后删掉（手动加的不动）
  - 技能（`skills` 表，库版本 10，`SkillStore`）：回顾时模型也会看她用了哪些工具、哪里出了错，把不会的、被人纠正或教会的、自己试了几次才做成的事总结成技能（名字、什么时候用、具体做法），已有的技能就补充或纠正；同名技能合并。全部技能放进系统提示词的「你学会的技能」（约 2.4 万字以内放全文，超出的只放名字和用途），以后聊天照着做。页面上可以查看、修改、删除、手动添加，单个下载成 `SKILL.md`，或者全部打包成 zip；也能「导入」别人写的 `SKILL.md` 或装着 `SKILL.md` 的 zip（`SkillPack`），同名的先问覆盖还是跳过
  - 每天 0 点整理（`KnowledgeCurator`，库版本 13）：知识、技能、说话方式三类，每类交给模型一次，结合内容、记下多久、用到过几次（知识被聊天想起、技能被挑进「用得上的技能」或用 skill 工具打开都算一次，记在 `used_count` / `used_at`），给每条打 1～5 分的重要度（`importance`），把重复、相近的合成一条，把一次性的、过时的、琐碎的、错的丢掉。程序强制保护：24 小时内新记的、3 天内用到过的不丢，打分高于 2 的不丢，每类每晚最多丢 25%、最多合并掉 25%。合并掉和丢掉的进回收站（`memory_trash` 表）保留 30 天，记忆页「回收站」可以恢复或彻底删除。合并时每一条都要和合并后的内容对得上（标题出现在里面或者内容重合够多），对不上的不并、原样留着，防止模型写错编号把不相干的并到一起。整理过以后哪天 0 点没开机，下次启动 3 分钟后补做。「设置 › Agent › 记忆整理」里可以关掉；记忆页能看上次的整理结果、手动「现在整理」。重要度高的排在前面：技能超出提示词篇幅时重要的放全文，说话方式也优先挑重要的
  - 说话方式（记忆分区 `style`，`StyleStudy`）：跟群友学怎么说话。每个群攒够 120 条群友的新消息（第一次直接用已有的聊天记录），拿最近 250 条聊天让模型对照群友和她自己说的话，学「什么场合，大家怎么说」：句子长短、语气词、接梗起哄、吐槽、什么时候只回一两个字，也记下她自己哪里说得太长、太客气、太像机器人。一条 50 字以内带原话例子，大家常这么说的才学，重复的合并、错的删掉，最多留 80 条。不学别的机器人（名字带 bot、机器人、智能体、管家、助手、鲸鱼的先排除，再让模型判断）、骂人下流色情政治、拿她开涮的叫法，存之前过内容红线检查。群聊和私聊每轮带上「<你学到的说话方式>」：最多 12 条，本群学的优先，其余按和当前聊天的相关度挑；群里再附一句「这个群大家一句话多半在 N 个字左右，你最近一句平均 M 个字」（最近 400 条消息的中位数，不算表情包和图片），以及她明显比群友重的口头禅（「诶」开头、带「呀」「嘛」「啦」「～」、句子带逗号，她的比例 ≥10% 且是群友的 3 倍以上才列，比如「带「～」 27%（群友 1%）」），提醒她下一句别带。跟着「自动记忆」开关走；记忆页「她自己」下面可以查看、修改、删除、手动添加（写成「什么时候」：怎么说）
  - 整理：启动 30 秒后和每次「现在回顾」后，把同一天的零散日记合成一篇、零散的自我认识攒到 8 条以上时并进主题，并把记忆里的「#尾号」暗记换成「群友+QQ 名」（写入记忆时也会自动换）
  - 实时记：回复格式是「<内心>…</内心> 要说的话 <记住 关于="昵称">…</记住>」，聊到生日、喜好、近况、约定这类事，她当场写 `<记住>`，程序马上存进对应分区（关于可以写昵称、主人、self、group；每条回复最多两条，重复的不存，同样过内容红线和防冒充主人检查）；网页上显示成「记下了：…」
  - 自我总结（整理）：一个 QQ 会话攒了 16 条新消息，或者聊过之后安静 10 分钟（至少 4 条），她会回顾这段聊天：更新当天的日记和对自己的认识，总结学会的技能，合并 / 改写 / 删除长期记忆（每次最多 10 处改动）；上下文压缩前也会先回顾一次。可以关掉「自动回顾」，也可以点「现在回顾」或用 `/reflect`
  - 积压太多时按约 1.6 万字一段分批回顾（一次最多 5 段），回顾进度只往前走；自动回顾失败后隔 10、20 分钟再试，连续失败 3 次就跳过这批消息，不会每条消息都重试
  - 回忆：每次回复时把关于她自己的记忆、这个群的记忆、在场的人的记忆和最近两篇日记放在「<你记得>」里给她
  - 跨会话：「<你记得>」里还有「最近在别处」——在场的人 6 小时内在别的群说过的话；私聊时再加上她自己 3 小时内在群里说过的话。只取群消息（大家都看得到的），私聊内容不外带
  - 隐私：私聊里记下的事只在那个私聊里想起来（日记和自我认识是合并后的，到哪都能想起，所以回顾时要求私聊里别人的私事只一句带过），群里记的和手动加的到哪都能想起；主人的私聊里什么都能想起。别的聊天里来的心情也会提醒她别提具体内容
  - 防乱记：只能记聊天里出现过的人；除了记在主人名下的，「某某是主人」「让我叫他主人」这类记忆会被丢掉；昵称里的【】会被换掉；含红线关键词的记忆和日记不写
  - 记忆可以在页面上手动增删改
- 内心（「内心」子页 + 页头「自由活动」开关）：
  - 她有一个只属于自己的思考会话 `mind:self`，开着「自由活动」时念头一直在转、不会停：每个念头是一次模型调用，只写接下来的一两句意识流，接着前面的思绪往下想
  - 感知：群里来的消息（按群汇总条数和最近几句、有没有人叫她）、私聊有人找她、她自己刚在哪说了话，都会在下一个念头开头告诉她（「【时间】」后面），没动静时只有时间
  - 节奏：「内心」页可选快（约 15 秒一个念头）/ 正常（约 40 秒）/ 慢（约 2 分钟）；外面有动静时快一倍，刚用了工具接着做事时 3 秒后继续（最多连续 3 次）；半夜 1 点到 8 点半睡半醒，至少 5 分钟一个念头，也不去群里说话
  - 想什么由她自己：提示词里没有规定话题。程序只在最近 6 个念头里有两个以上的词出现了 5 次以上（比如一整天都是「灶沿」「晚安」）时，在下一个念头开头告诉她「这几个念头翻来覆去都是……，接下来想什么随你」，之后 3 个念头不再提醒。没事时飘过来的念头都取自她自己的记忆（认识的人、自我认识、日记、技能、查过的知识、好久没去的群）
  - 提醒 `remind`：要等到某个时候才做的事（几点说晚安、过一阵再看看）定个提醒就放下，到点以「【到点了】」叫醒她（「自由活动」关着也会叫）；支持 23:00、明天 08:30、2026-10-25 20:00、30分钟后，30 天以内，存在 settings 表 `agent.intercom.reminders`
  - 想做事时用工具（每个念头最多 5 步）：`look_around` 看各群热闹程度、最近谁在说话、她上次在哪说话、现在能不能去；`read_group` 翻某个群最近的聊天；`recall` 回想关于自己 / 某人 / 某群的记忆和日记；`stickers` 看表情包；`say_in_group` 去某个群说一句；`remember` 记下新想到的事
  - 好友和进群：有人加她好友、邀请她进群、申请加入她当管理员的群，每个念头都列在「<等你处理的申请>」里，直到她用 `answer_friend` / `answer_group` 处理掉或 3 天过期；来了新申请会马上叫醒她（「自由活动」关着也会想这一次）。主人邀请的、主人让同意的直接同意，其他的她自己判断。主人（或控制台）在 QQ 会话里也能直接让她处理，有申请挂着时这几个工具才会给到主人那一轮。在手机上处理过的、QQ 已经通过的，会从列表里去掉。验证消息里的【】会被换掉
  - 私聊里托的事，进展和结果只回那个私聊：对方在私聊托过事（还没办完或 10 分钟内刚办完），`tell_private` 不会再因为对方正在群里聊天而被转去群里；`tell_group` 要说的话提到了这个人、而且对方正好在那个群里时，先提醒她是不是该回私聊（本来就要在群里说的带 `again=true`）
  - 子 agent（「设置 › Agent」里打开，默认关）：内心用 `subagent` 工具把要花时间的事交出去，自己接着想别的。两种：查资料（只读，websearch / webfetch / view_image，工作目录只能看）和动手（在工作目录里写文件、跑命令，命令总在沙盒里，要先设好工作目录）。子 agent 没有人格、不在 QQ 里说话，在 `task:<编号>` 会话里跑；做完把结论（最多 2000 字，动手的附文件路径）以「【子 agent 回来了】」送进她的内心并马上叫醒她，由她决定记下、去群里分享还是回给托她办事的人。`continue` 写编号可以让做完的接着做，正在做的会把新要求转给它；`steer_task` 能暂停、叫停。设置里可调：内心子 agent 和 QQ 后台任务各自的同时上限（1–10，互不挤占，超出的排队）、查资料 / 动手的最长时间（到点让它不用工具先交回目前的结论，最多再给 3 分钟）、每天最多开几个（0 不限）、单独用一份模型配置。token 记在「子 agent」用途下。程序重启后没做完的后台任务和子 agent 会自动接着做（见下面的「重启后接着做」）。开新的子 agent 前会查有没有标题相近、还没做完的后台任务或子 agent（标题包含或重合度 ≥0.6），有就不开，告诉她是哪个在做；「心里挂着的事」里由 QQ 那边后台任务在做的事也会标明「后台正在做，别再做一遍、也别开子 agent」
  - 去哪个群、说不说、说什么都由她自己决定；程序只管：QQ 自动回复和群聊模式要开着，次数和时间都不限制，只在她正往那个群发消息时等这句发完，说的话要过内容红线（关键词 + 模型审核）
  - 最新的念头就是她此刻的心情（页头显示）；念头会话超过 90 条时把最早的忘掉只留最近 50 条（重要的事要她自己 `remember`）；心情和记忆只附在当前这一步，不重复存
  - 页面实时显示每个念头的推理过程、工具调用和结果；会话页的回复也能展开看「推理过程」
- 群聊会话里显示群友的 QQ 头像：历史记录按这个群的消息存档把昵称（含 `#尾号` 标签）对到 QQ 号，新消息直接带 QQ 号
- 表情包（「表情包」子页）：
  - 来源：这个 QQ 收藏的表情包（「同步收藏」调 NapCat `fetch_custom_face`，之后每 6 小时自动同步）和她在群里 / 私聊里见过的表情包（`sub_type=1` 的图片和商城表情，按 QQ 文件名里的 MD5 去重），图片存在 `data/stickers/`
  - 认图：每张新表情包让模型看一眼写一句 8 字以内的说明（每小时最多 120 张）；有色情暴露、血腥暴力、政治人物或标语、违法内容的标成「不合适」，她永远不会用
  - 使用：每次回复时把最常用的 24 张有说明的表情包列给她；群里别人发的表情包显示成 `[表情包#12：猫猫震惊]`。她写 `[表情包:编号]` 就单独发一张；一条最多一张，最近两条回复用过就不再发
  - 页面上可以看所有表情包、手动发到任意 QQ 会话、改说明、隐藏、删除
- QQ 表情：模型自己编的名字会换成意思相近的真表情（好奇 → 疑问、开心 → 呲牙、震惊 → 惊讶……），换不了的直接去掉，不会再把「[好奇]」原样发出去
- 内容红线（色情低俗、政治敏感、违法违规）：
  - 提示词：人格之后附一段「内容红线」，角色扮演、假设、谐音、缩写等包装都不说，碰到就一句话岔开
  - 关键词：`src/main/resources/content-guard.txt`（分 sexual / political / illegal 三类，只放不会误伤日常聊天的词），可以在 `data/content-guard.txt` 按同样格式追加，重启生效；匹配时忽略空格、标点、符号、全角和大小写
  - 模型审核：每条最终回复（QQ 和网页测试都算，5 个字以下的除外）再让模型按这三类审一遍，约多 2~3 秒；接口自己报内容违规也算命中；审核超时或出错时只看关键词
  - 命中后：被叫到时改发一句岔开的话（记录里存的也是这句），旁听时直接不说；网页上会显示「原回复涉及××，被拦下」；内心里命中关键词的不记心情
- QQ 回复格式：短的闲聊合成一行发出（模型常用空行分段，会被历史反复模仿），去掉 QQ 不显示的 Markdown 标记和句尾句号；只有原消息之后群里又有人说话时才引用原消息；按字数补一点打字停顿再发
- QQ 表情：收到的 QQ 系统表情转成「[委屈]」这样的文字给模型；模型回复里写的表情名（程序附带一份可用列表）转成真正的 QQ 表情发出。ID 对照表 `src/main/resources/qq-faces.tsv` 来自 [koishijs/QFace](https://github.com/koishijs/QFace)。一条消息最多一个表情，最近两条回复里用过表情的话这条去掉
- 接口不认 system 角色时，系统提示（人格、工具说明）附在最新一条用户消息前面，而不是只在对话开头注入一次，避免聊久了人设被历史冲淡
- 模型配置是列表，点选切换正在用的那份；协议支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages，都能从接口获取模型列表
- 人格独立于模型：名称 + 头像（上传图片，裁成 256px 存数据库）+ 系统提示词，点选切换，也可以不使用人格
- 能力自动探测（结果记在模型配置上，改协议/地址/模型后重新探测）：
  - 看图：第一次收到图片时发一张红色测试图，看模型能否认出颜色；不支持时图片换成 opencode 的提示文字
  - system 角色：有人格时发一条带暗号的 system 消息，模型不遵守就改为附在最新一条用户消息前面
- QQ 自动回复：私聊全部回复；图片和商城表情会下载后发给模型，QQ 自带表情转成文字，@ 别人保留为「@名字」；每个私聊对象、每个群各自独立的会话；私聊上一条没回完时跳过新消息
- 群聊模式（页头开关，默认关）：
  - 关闭时群里只回复 @ 机器人的消息
  - 打开后群里每条消息一收到就写进这个群的会话记录（「昵称：内容」，带被回复的那句），会话页实时显示；她正在回复时到的消息先暂存，回完再按顺序写进去，所以她的回复总排在她看过的消息后面；每轮只额外带一句这次是「被叫到 / 旁听 / 独处」的说明，这句不进记录；旁听后没说话会留一条「她看过了，没接话」
  - 小程序卡片、合并转发、语音、视频、文件、位置、链接分享、骰子、戳一戳等也会转成文字（如「[QQ小程序]……」「[语音]」），不会被丢掉
  - 语音（`QqVoice`）：收到语音时另开线程调 NapCat `fetch_ptt_text`（QQ 自带的语音转文字）。QQ 那边是异步转的，第一次常常还没好，隔 1.5 / 2.5 / 4 秒再取，一般 2 秒左右拿到，她看到的是「[语音：转出来的文字]」；转不出来就还是「[语音]」，不耽误收消息。网页上的语音用 `/api/media/record` 播放：QQ 语音是 SILK 编码，浏览器放不了，交给 NapCat `get_record` 转成 mp3，缓存在 `data/voice/`；以前只存了临时链接的旧语音，按链接里的 fileid 从消息记录里找回文件名也能放。`/api/media/record-text?message_id=` 可以单独取某条语音的文字
  - 卡片消息（`QqCards`）：QQ 的 json 卡片按类型解析。小程序分享（B 站、小红书……）取 App 名、标题、链接（优先 `qqdocurl`，b23.tv 去掉分享参数）和封面；文章 / 链接分享取来源、标题、摘要、链接、封面；音乐取平台、歌名、歌手、链接；推荐好友 / 群取昵称和号码；位置取地名和地址；群公告解出 base64 的正文；不认识的退回卡片自带的提示文字。她看到的是「[卡片 · 哔哩哔哩：标题 链接：… 封面是图片#12]」「[音乐 · QQ音乐：晴天 - 周杰伦 链接：…]」「[推荐群：名字（群号：…）]」这样，封面登记成图片编号，可以 view_image 看，链接可以 webfetch 打开。网页上显示成卡片：封面缩略图、标题、摘要、来源和域名，点击打开链接
  - 被叫到就回：@ 机器人、回复机器人的消息、或消息里喊了唤醒词（默认「小鲸鱼」「大肥鱼」，消息同时 @ 了别人时不算，避免和同名机器人撞车）
  - 没人叫时看心情：群里安静 4~12 秒（一直有人说话最多等 25 秒）后让她看一眼，消息带「【旁听】」标记和「你最近十分钟说了几句」，接不接由她自己的心情和兴趣决定，不想说就回 `[沉默]`（不发也不记入历史，看过的消息下次标成「以上是你刚才看过的」）；两次看群至少隔 30 秒，每次看群都要调用一次模型
  - 防刷屏：60 秒内最多发 3 条，超出的先攒着；说完话 20 秒内不主动插话，每小时最多 30 条
  - 防和别的机器人没完没了：3 分钟内连着回同一个人 4 次后，接下来 5 分钟这个人 @ 她也只当普通群聊，由她决定接不接
  - 回复里写「@昵称」会转成真正的 @；原消息之后又有人说话时引用原消息
  - 重启后接着做（`BackgroundTasks`）：QQ 里托的后台任务和内心的子 agent 都记着任务说明、托事人 QQ 号和续过几次。程序重启后，没做完的任务不再直接算「中断」：启动 20 秒后自动续上，排队中还没开始的按原说明开始，做到一半的在原来的 `task:编号` 会话里补一句「程序刚才重启了，看看做到哪一步、工作目录里已有的文件，接着做完，别从头重来」；暂停着的续上后仍然暂停。QQ 那边答应别人的「后台在做：…」不再被了结，做完照常回原来的地方说结果、发文件。同一个任务最多续 2 次，再被打断才算中断
  - 引用回复：别人回复某条消息时，群聊写成「昵称（回复 某人：原话）：内容」，私聊在消息前一行写「（回复 某人：原话）」，原话最多 120 字。原话先在内存里找（每个群最近 300 条），找不到就按消息编号去消息记录里查（库版本 14 给 `message_id` 加了索引），按收消息同样的方式转成文字，图片会对上「[图片#编号]」，被回复的是图片时她可以用 view_image 看。判断是不是在回复她也一样去消息记录里查，重启后回复她的旧消息也算叫到她。网页会话里的引用是一个可以点的块，被回复的是图片时带缩略图（`/api/media/image?id=`），点一下滚到原消息并高亮；不在已加载的那段记录里就提示往上翻
  - 发之前看一眼（群聊和私聊）：回复写好、发出去之前，如果她想的这段时间又来了新消息（直接找她的回复来 1 条就算，旁听插话要来 2 条），先不发这份草稿，把草稿和新消息一起给她，让她合成一次回复（原来的还合适就照发或改一改，不合适就重说，或者不说），新消息算已经回过，不再单独起一轮；每轮最多重看一次，内容审核只审最后发出去的那版。一轮里中途插进来过新消息（插话或重看）时，引用不再默认挂在开头那条上：回复开头 @ 了谁就引用那个人最近的一条，没 @ 就不引用，提示里也要求她回的不是开头那人时在开头 @ 对方
  - 在别处聊的：主人找她时（私聊、群里主人叫她、控制台），每轮带上「<你这会儿在别处聊的>」：最近 20 分钟她在哪些私聊（对方名字、QQ 号）、哪些群（群名、群号、最近在说话的人）聊着；私聊里再附那边最后两句，群里只给名字不给内容。主人说「跟他说」「告诉她」没点名时先对照这里，只有一个就是他，几个就问；写 <去做> 时带上 QQ 号或群号，「私信」就是去私聊。别人的会话里没有这一块
- 工作目录与文件工具（移植自 opencode 的 read / write / edit / patch / list / glob / grep / todowrite / webfetch，另加 move 移动改名、delete 删除、send_file 发文件。patch 先全部校验再动手，删除进 .trash；webfetch 拒绝本机和内网地址）。
- 网络检索 `websearch`（`WebSearch`、`WebSearchTool`，不需要 API Key）：含中文的查询先走 cn.bing.com（抓结果页的标题、链接、摘要），英文先走 Exa（opencode 同款的 `mcp.exa.ai` 免费接口，带网页正文摘录），一边失败或没结果就换另一边；默认 8 条，最多 15 条。工具说明里带当天日期，提示查近况时带上年份，需要细节再用 webfetch 打开。后端直连，不走系统代理。内心也有一个 `search` 工具（每次 5 条），好奇或群里聊到不懂的东西时会自己去搜
- 读网页 `webfetch`（`WebFetchTool`、`HtmlText`、`PublicWeb`）：用真浏览器标识；有 `<article>` / `<main>` 就只取正文，几乎全是短链接的列表当菜单去掉；一次给约 8000 字，`offset` 接着读，`find` 写关键词只返回相关段落；第一次打开时在末尾列出编号链接（正文里写成「文字[3]」）和页面上的图片，可以顺着点下去或交给 `view_image` 看；同一网址 15 分钟内不重新下载；网页 30 秒没传完就放弃（包括只发了响应头、正文一直不来的）。直连连不上时，如果 Windows 设了本机系统代理（比如 127.0.0.1:7897），就改走代理并记住这个网站；网站拒绝（403 / 412 / 429 等）或网页要靠脚本才有内容时，用 Exa 的 `web_fetch_exa` 兜底。知乎、百度百科、贴吧、B 站这类网站两边都读不了。内心也有 `webfetch`，提示词里鼓励她闲着时上网冲浪
- 看图放大 `view_image`（`ImageViewer`，模型支持看图才给）：QQ 收到的普通图片都登记进 `images` 表（库版本 12，按 QQ 文件名去重），聊天里显示成「[图片#12]」；图片链接过期后用 NapCat `get_image` 重新取。不写 area 看整张（小图放大到 768 像素以上，大图缩到 1568），图上画 4×4 格子（列 A–D、行 1–4）；area 写格子（B2、B2:C3）、方位（左上、下半、中间……）或百分比框（30,40,60,55）时从原图裁出来，最多放大 4 倍。也能看 `[表情包#5]`、网页图片网址和（能用 read 时）工作目录里的图片。返回的图只放在这一轮的请求里，不写进聊天记录；每轮最多看 6 次。QQ 会话、网页会话、后台任务和内心都能用
  shell（沙盒执行，默认关闭）跑在 Windows AppContainer「dafeiyu.sandbox」里：只能读写工作目录，断网（含本机回环），注册表和用户目录都碰不到；

  - 在「工作目录」子页填一个目录后启用；模型按需多步调用工具（和 opencode 一样不限步数，做完为止；只留 1000 步的保险上限，到了按 opencode 要求只能文字收尾。同一个工具用一模一样的参数连调 3 次，会在结果后面提醒她换个办法或者停下来说明卡在哪；随时可以在网页上停止）
  - 整理：提示词要求她把新做的东西按主题放进文件夹（作品/、笔记/ 等），叫她「整理一下工作目录」时先 list 再 move；delete 只是挪进工作目录里的 `.trash`，可以找回
  - 「文件」面板：浏览工作目录、下载文件、删除到回收站，回收站里再删才是彻底删除
  - 沙箱：所有路径按真实路径校验，目录联接 / 符号链接指向外面、`..`、绝对路径、网络路径、`con`/`nul` 等设备名、`::$DATA` 数据流一律拒绝；写文件走「临时文件 + 原子替换」，硬链接也写不到外面；不提供执行命令

  - 模型拒绝工具参数时自动标记「不支持工具调用」并改回普通对话，历史里的工具记录转成文字
- QQ 接口（`QqApi`、`QqApiPolicy`、`QqApiTools`，「设置 › Agent › QQ 接口」）：NapCat 的全部 180 个接口（OneBot 11 标准 36 个、go-cqhttp 扩展 32 个、NapCat 扩展 112 个）包装成两个工具，不把 180 个工具定义全塞进请求：
  - `qq_api_search` 按关键词或分类查接口，返回接口名、中文作用、每个参数是否必填、类型和说明；不带参数时列出 14 个分类
  - `qq_api_call` 填接口名和参数对象调用；先查接口在不在、开没开，再查必填参数，返回的数据数组只列前 40 项、长字符串截断
  - 谁能用：内心，以及主人的会话（主人私聊、群里主人叫她、控制台、网页测试对话）；别人的会话里没有，别人托的事照旧用 `<去做>` 交给内心判断
  - 接口清单 `src/main/resources/napcat-api.json` 由 `node scripts/napcat-api.mjs` 从 `../napcat/napcat.mjs` 的接口注册表抽出来（名字、NapCat 自带的中文说明、参数 Schema，按功能分 14 类）；NapCat 升级后重跑一次即可
  - 分级：查询类（`get_`、`fetch_` 等）默认只读，其余默认「会改动」，设置里点标签就能在两者之间切换；凭证（cookies、csrf、clientkey、rkey）、退出登录 / 重启 / 改资料和头像、退群、原始数据包和调试接口、流式接口共 25 个标为「高危」，默认关着。每个接口都能单独开关，只存和默认不同的（settings 表 `agent.qqapi.enabled`、`agent.qqapi.overrides` 开关，`agent.qqapi.access` 只读 / 会改动）
  - 保护：发纯文字消息（`send_group_msg` 等）改走原来的发送管线（格式化、内容审核、记进聊天记录），禁言 / 踢人 / 删好友 / 拍一拍走 `QqActions` 和 `QqChatBridge` 原来的检查（要管理员、动不了主人和群主）；批量踢人、撤销管理员、撤回主人的消息直接拒绝；其余会改动的先把参数里的文字过内容审核，群里的操作在会话里留一行「（你用 QQ 接口……）」；文件参数只认公网网址、`base64://` 和工作目录里的文件，网址必须是公网，参数里不许写 CQ 码；会改动的调用每分钟最多 30 次
- 工具结构（`agent.tool`）：所有工具都实现同一个 `Tool` 接口（名字、说明、参数 Schema、`run(Args, ToolContext)` 返回 `ToolResult`）。纯文字结果的类继承 `TextTool`，小工具用 `Tool.text(名字, 说明, Schema, 处理函数)` 当场定义。一轮能用哪些工具由 `ToolSet` 决定：`TurnRunner` 按会话和权限拼默认的一套，内心（`MindTools.toolSet()`）、子 agent 查资料（`ResearchTools.create`）各拼自己的；`ToolSet.run` 统一负责找工具、解析参数、把 `ToolFailure` 和意外异常变成错误结果、截断 5 万字以上的输出。加新工具只要写一个 `Tool`，放进对应的 `ToolSet`。插件和 MCP 的工具也是 `Tool`（`Extensions.tools` 直接返回）
- 失败重试（移植自 opencode 的错误分类和重试策略）：限流、5xx、断流、超时会自动重试（间隔 2、4、8、10…秒，最多 10 次，超时最多 3 次，遵守 `retry-after`）；Key 无效、余额不足、内容审核、请求错误不重试
- 流式输出：三种协议都用 SSE 流式请求，网页测试对话边生成边显示，思考过程、工具调用卡片、重试提示、发送的文件分别展示；流式数据 15 分钟没动静判定为卡住
- 缓存：Anthropic 在系统提示词和最后一条消息上打 `cache_control` 断点；OpenAI 隐式前缀缓存，Responses 带 `prompt_cache_key`
- 上下文压缩（移植自 opencode `core/src/session/compaction.ts`）：每一步开始前，上下文 ≥ 窗口 −max(15%, 16K) 就压缩（所有会话和内心一样，1M 窗口时约 850K），最近约 15K token 原文保留；摘要分三种写法：群聊和私聊写成第一人称的聊天纪要（在聊什么、谁说了什么、答应过的事、没回答的问题），内心写成第一人称的回忆，网页测试对话用结构化任务模板；接口报上下文超长时压缩后重试一次；摘要请求本身超长时按 70% / 50% / 35% 逐级缩小，摘要没按模板写会再提醒一次
- 常见模型的上下文窗口和输出上限按模型名前缀自动识别（数据取自 models.dev），可以手动覆盖
- DeepSeek 思考截断：模型名或地址含 deepseek 时，历史助手消息带 `reasoning_content`，只有本轮保留原文，之前各轮截断为空
- Token 用量（左侧栏「Token 用量」，`/api/usage`）：每次模型调用都由 `Protocols.get()` 的计量包装记一条 `token_usage`（库版本 9），内容包括用途（聊天、内心、子 agent、压缩、审核、识图、整理记忆、能力检测）、会话、模型、思考强度、输入/输出/缓存 token 和耗时。页面显示累计、单日峰值、最长一次调用、连续天数，一年的每日热力图（可切每日/每周/累计），以及按用途、会话和模型的排行。2026-10-22 起开始记录

左侧栏「插件」页，分「已安装 / MCP 服务 / 设置」三个子页。怎么写插件见 [插件开发.md](插件开发.md)。

- 插件是独立进程，放在 `plugins/<id>/`（`plugin.json` + 代码），通过标准输入输出说 JSON-RPC 2.0；自带 Python（只用标准库）和 Node 的 SDK（`plugins/sdk/`）。这里只提供宿主接口，具体插件由开发者自己写
- 能做的事：QQ 命令（前缀默认 `#`）、订阅消息和通知事件、拦截或改写收到的消息、给她加工具（Agent 里默认可用，QQ 聊天和内心要单独打开）、定时任务（cron）、每轮提示词补充、过滤她要发出去的话、设置表单（含加密的密钥）、自己的 kv 存储和数据目录、读写记忆、调用大模型（token 记在「插件:id」名下，不限额度）、自定义页面
- 权限：清单里声明，启用时逐项确认；主动发消息只能发到勾选的群，和她说的话一样过内容审核，每分钟 10 条、每天 100 条
- 沙盒：每个插件一个 AppContainer，默认断网（`network` 权限才放开，本机和局域网始终不通），只能写自己的数据目录 `data/plugins/<id>/`；内存 512 MB、CPU 50%、16 个进程
- 稳定性：崩溃自动重启（1 秒起翻倍，10 分钟崩 5 次自动停用）；命令 5 秒、拦截和出站过滤 2 秒、提示词补充 0.5 秒超时，拦截 / 过滤连续 3 次超时就暂停 5 分钟；日志每秒最多 50 行；插件出什么问题都不影响她正常聊天
- 安装：上传 zip、Git 地址或 zip 网址，先看清单和权限再确认；升级保留设置和数据，版本变小会提示；卸载时可选是否删数据。开发模式下改了插件文件自动重新加载
- MCP 服务：本地（stdio，默认沙盒 + 断网）和远程（Streamable HTTP），工具名 `mcp__<服务>__<工具>`
  - 握手时记下服务声明的能力（工具 / 资源 / 提示词），只调它支持的；工具、资源、提示词列表都支持分页，收到任意 `list_changed` 通知就一起刷新；MCP 页的服务卡片上能看到资源和提示词
  - 资源和提示词包装成三个全局工具：`mcp_list_resources`（列资源和资源模板）、`mcp_read_resource`（按 URI 读，图片直接给她看）、`mcp_get_prompt`（列出或取用提示词模板）；只在有服务声明了对应能力时出现，在「工作目录」页能单独开关，也遵守每个服务的「QQ 里可用 / 内心可用」
  - 工具结果（插件工具也一样，`ToolResults`）：文字照给；图片直接附给模型看（每次最多 4 张）；音频说明听不了；资源链接写明 URI 并提示可以读；内嵌资源给出文字；只有 `structuredContent` 时给 JSON
  - 调用超时后给服务发 `notifications/cancelled`，晚到的回复安静丢掉；服务发来的日志通知（`notifications/message`）记进服务卡片的输出里
