# 插件开发

给 FeiYu Bot 写插件的完整说明：从零写一个命令插件、清单每个字段、每个接口、沙盒、调试、打包。

扩展她有三种方式，按需要选：

| 方式 | 适合 | 怎么装 |
|---|---|---|
| **插件** | 命令、定时任务、拦截消息、给她加工具、自定义页面 | 放进 `plugins/<id>/`，或在「插件」页上传 zip / 填 Git 地址 |
| **MCP 服务器** | 已经有现成的 MCP 服务，只想给她加工具 | 「插件 › MCP 服务」里添加 |
| **技能包** | 只是知识和做法（`SKILL.md`），不需要跑代码 | 「Agent › 记忆 › 技能」里点「导入」 |

插件是独立的进程，通过标准输入输出和主程序说 JSON-RPC。用什么语言都行；仓库里带了 Python 和 Node 的 SDK，下文以 Python 为主。

## 1. 五分钟写一个命令插件

目标：群里发 `#掷骰子`，回一个 1～6 的数。

**第一步**：在 `dafeiyu/plugins/` 下建文件夹 `dice`（文件夹名就是插件 id）。

**第二步**：写 `plugins/dice/plugin.json`：

```json
{
  "id": "dice",
  "name": "掷骰子",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "发 #掷骰子，回一个 1～6 的数",
  "host": ">=0.2.0",
  "run": { "command": "python", "args": ["main.py"] },
  "permissions": ["qq.reply"],
  "commands": [
    { "name": "掷骰子", "aliases": ["dice"], "description": "掷一个骰子" }
  ]
}
```

**第三步**：写 `plugins/dice/main.py`：

```python
import random

from feiyu_plugin import Plugin

p = Plugin()


@p.command("掷骰子")
def dice(ctx):
    ctx.reply(f"{ctx.sender} 掷出了 {random.randint(1, 6)}")


p.run()
```

`feiyu_plugin` 不用安装，主程序启动插件时会把 SDK 目录放进 `PYTHONPATH`。

**第四步**：打开控制台「插件 › 已安装」，点「重新扫描」（刷新图标），找到「掷骰子」，打开开关，同意 `qq.reply` 权限。状态变成「运行中」就好了。

**第五步**：在群里发 `#掷骰子` 或 `#dice`。插件处理了的命令，她不会再回一遍。

写的时候建议打开「插件 › 设置」里的**开发模式**：改了插件文件，几秒内自动重新加载，不用手动点。

照着改：
- 想让她能用（聊天时自己调用）→ 加一个[工具](#43-工具)
- 想每天定时做事 → 加[定时任务](#44-定时任务)
- 想让用户填配置 → 加[设置项](#47-设置项)

## 2. 目录结构

```
plugins/
├─ sdk/                     SDK（feiyu_plugin.py、feiyu_plugin.js），不要改
└─ <id>/                    你写的或装上的插件
   ├─ plugin.json           清单（必须）
   ├─ main.py / main.js     入口，名字随意，在 run 里写
   ├─ README.md             说明，插件详情页里显示
   ├─ icon.png              图标（可选，正方形）
   └─ web/index.html        自定义页面（可选，见 4.8）
```

- 插件 id 只能用小写字母、数字、`-`、`_`，2～40 个字符，并且**必须和文件夹名一样**。
- 插件自己的数据放在 `data/plugins/<id>/`（环境变量 `FEIYU_DATA_DIR`），升级和重装都不会删；卸载时可以选是否一起删。
- 插件文件夹在沙盒里是**只读**的，要写文件就写到数据目录。
- `plugins/` 下除了 `sdk/` 都不进 git。现成的插件放在仓库的 `plugin` 分支里，每个插件一个文件夹（比如 #sl 防召唤 `sl-guard/`），和主程序的历史分开；在「插件 › 已安装 › 安装插件」里填 `https://github.com/GzSakura1338/FeiYu-Bot/archive/refs/heads/plugin.zip` 就能装。

## 3. plugin.json

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 和文件夹名一致，`[a-z0-9][a-z0-9_-]{1,39}` |
| `name` | ✓ | 显示的名字 |
| `version` | ✓ | `主.次.修订`，比如 `1.2.0`。升级时版本号变小会提示降级 |
| `author` | | 作者 |
| `description` | | 一句话说明 |
| `host` | | 要求的主程序版本，如 `>=0.2.0`、`^0.2.0`、`=0.2.0`。现在的主程序版本是 **0.3.0**（0.3.0 起拦截可以返回 `hide`，用到它的插件写 `>=0.3.0`）。不满足时插件显示「版本不兼容」，不会启动 |
| `run.command` | ✓ | 启动命令：`python`、`node`，或者可执行文件 |
| `run.args` | | 参数，路径相对插件文件夹 |
| `run.env` | | 额外的环境变量（对象） |
| `permissions` | | 要的权限，见[第 4 节](#权限)。启用时会让你确认 |
| `commands` | | 命令列表：`name`（不能有空格、`#`、`/`，最多 20 字）、`aliases`、`description`、`scope`（`["group"]`、`["private"]` 或都要，默认都要） |
| `events` | | 订阅的事件，见 4.2 |
| `intercept` | | `true` 时收到消息先问插件要不要拦下，需要订阅 `message.group` 或 `message.private` |
| `priority` | | 拦截和过滤的顺序，数字小的先，默认 100 |
| `tools` | | 给她用的工具，见 4.3。最多 20 个 |
| `toolTimeout` | | 工具默认超时秒数，1～600，默认 60 |
| `schedules` | | 定时任务：`id`、`cron`、`description` |
| `prompt` | | `true` 时每次她回复前问插件要一段提示词补充 |
| `filter` | | `true` 时她发出去的每句话先过插件，需要 `qq.filter` 权限 |
| `settings` | | 设置项，JSON Schema 的一个子集，见 4.7 |

清单写错时，插件页会显示「清单有问题」并逐条列出哪个字段错了，主程序照常运行。

### 权限

| 权限 | 能做什么 |
|---|---|
| `qq.reply` | 回复触发它的那条命令、消息或通知。最常用、最安全 |
| `qq.send` | 主动往**你勾选的群**发消息（插件详情里的「允许发消息的群」），能用 `qq/groups` 列出这些群 |
| `qq.private` | 主动发私聊、读私聊记录 |
| `qq.read` | 读勾选的群的聊天记录、群列表、群成员 |
| `qq.filter` | 她要发出去的话先给插件过一遍，可以改写或拦下 |
| `qq.api` | 直接调协议端的原始 QQ 接口（发语音、戳一戳、群文件…）。**能力最强、风险最高**，锁死的（凭据/账号/内部/流式）一律拒绝 |
| `memory.read` | 读她的记忆（私聊里记下的不给） |
| `memory.write` | 往她的记忆里加一条 |
| `mind.read` | 收到她内心的念头（`bot.thought` 事件） |
| `llm` | 用她当前的模型做一次对话，token 记在 Token 用量页「插件:id」名下，不限额度 |
| `network` | 插件进程能上网（本机和局域网仍然不行） |
| `files` | 能读写你设置的工作目录（路径在环境变量 `FEIYU_WORKSPACE`） |

没声明的权限调了会被拒绝（错误码 `-32001`），并记一条安全日志。插件升级时如果多要了权限，会重新问你。

不需要权限的：`kv/*`、`log`、`notify`、`tools/changed`。

## 4. 能做的事

### 4.1 命令

```python
@p.command("今日人品")          # 用 name，不是别名
def jrrp(ctx):
    ctx.reply(f"{ctx.sender}，你今天的人品是 42")
```

- 命令前缀默认 `#`，在「插件 › 设置」里可以改。`@她 #命令` 也算。
- `ctx.args` 是命令后面的整段文字，`ctx.argv` 是按空格切开的列表。
- 处理函数返回 `False` 表示「这条我不管」，消息照常交给她回复。
- 命令处理超过 **5 秒**，消息交给她回复，插件迟到的回复会被丢弃。
- 两个插件抢同一个命令名（包括别名）时，插件 id 按字母排在前面的生效，另一个在插件页显示冲突。

### 4.2 事件与拦截

```python
@p.on("notice.join")
def joined(ctx):
    ctx.reply(f"欢迎 {ctx.user_id}")
```

| 事件 | 什么时候 |
|---|---|
| `message.group` / `message.private` | 收到群消息 / 私聊 |
| `notice.join` / `notice.leave` | 有人进群 / 退群 |
| `notice.recall` | 有人撤回消息 |
| `notice.poke` | 拍一拍 |
| `bot.said` | 她发出了一句话 |
| `bot.thought` | 她冒出一个念头（需要 `mind.read`） |
| `bot.connected` / `bot.disconnected` | QQ 连上 / 断开 |

普通订阅是「旁听」：插件收到通知，不影响她，插件处理多慢都不会拖慢她。

要**拦截**消息，清单里写 `"intercept": true`，再用 `@p.intercept`：

```python
@p.intercept
def on_message(ctx):
    if "群规" in ctx.text:
        ctx.reply("群规在群公告里")
        return "drop"              # 吞掉，她不回这条（这条还会进会话，她之后能看到）
    if ctx.text.strip() == "#sl":
        return "hide"              # 藏起来：她不回、不进会话，内心翻群记录也看不到
    if ctx.text.startswith("翻译 "):
        return ("rewrite", "请把这句翻译成英文：" + ctx.text[3:])   # 改写后交给她
    return "pass"                  # 原样交给她
```

- `drop` 和 `hide` 的区别：`drop` 只是不让她回这条，消息照样记进会话，她之后接话时能看到；`hide` 连会话都不进，适合别的机器人的指令、刷屏这类她最好完全看不到的东西。两种都照常进消息记录和事件日志。`hide` 要主程序 0.3.0 以上。
- 多个拦截插件按 `priority` 从小到大依次过；前一个 `drop` 或 `hide` 了，后面的不再收到。
- 拦截超过 **2 秒**按放行处理；**连续 3 次**超时，这个插件接下来 5 分钟不再经过（重新加载后恢复）。
- 重连后补发的旧消息带 `backfilled: true`，不会走拦截，只通知旁听。

消息上下文 `ctx` 的字段：`type`、`session`（`group:<群号>` / `private:<QQ>`）、`group_id`、`user_id`、`sender`、`owner`（是不是主人）、`text`、`message_id`、`mentioned_me`、`backfilled`，原始数据在 `ctx.data`。

### 4.3 工具

```python
@p.tool("current", "查某个城市现在的天气", {"city": {"type": "string", "description": "城市名"}})
def current(city):
    return f"{city} 晴，20°C"
```

- 她看到的工具名是 `plugin__<插件id>__<工具名>`。
- 参数按 JSON Schema 校验，不合法的调用不会到插件。
- 返回字符串、或能转成 JSON 的值；也可以返回 MCP 格式的 `{"content": [...], "isError": false}`。结果超过 5 万字会被截断。
- 工具在 **Agent** 里默认可用（可在工作目录的工具列表里关掉）；在 **QQ 聊天**里要到插件详情打开「QQ 聊天里也能用这些工具」；清单里写 `"mind": true` 的工具她在内心活动时也能用。
- 工具会变时（比如按设置启用不同工具），调 `p.tools_changed()`，宿主会重新拉取列表。
- 也可以不在清单里写 `tools`，只用 SDK 注册：启动时 SDK 会把工具列表报给宿主。

### 4.4 定时任务

```json
"schedules": [{ "id": "morning", "cron": "0 8 * * *", "description": "每天 8:00" }]
```

```python
@p.schedule("morning")
def morning():
    for g in p.groups():                    # 插件详情里勾选的群
        p.send(group_id=g["groupId"], text="早上好")
```

- cron 五段：分 时 日 月 星期（0 和 7 都是周日），支持 `*`、`*/5`、`1-5`、`1,3,5`。日和星期都限定时取并集。时区是本机时间。
- 插件详情的定时任务旁边有「立刻执行」，方便调试。
- 主程序没开着的时候错过的不补。

### 4.5 提示词补充

清单写 `"prompt": true`：

```python
@p.prompt
def prompt(session, people):
    return "今天是社团活动日，群里的人可能会问活动地点：三楼会议室。"
```

- 每次她回复前调用，`people` 是在场的人的 QQ 号。
- 返回的文字包在 `<插件:名字>…</插件:名字>` 里放进她的提示词，最多 300 字。
- **500 毫秒**内没返回就跳过这一轮。

### 4.6 出站过滤

清单写 `"filter": true`，权限要 `qq.filter`：

```python
@p.filter
def filter_text(session, text):
    if "敏感词" in text:
        return "drop"                       # 拦下，她会知道这句没发出去
    return text.replace("你好", "您好")     # 返回字符串就是改写
```

- 改写后的话会再过一遍内容审核，插件没法绕过红线。
- 出站过滤里返回 `"hide"` 和 `"drop"` 一样，都是拦下。
- 超过 2 秒按放行处理，连续超时同样会被暂停 5 分钟。

### 4.7 设置项

```json
"settings": {
  "type": "object",
  "required": ["city"],
  "properties": {
    "city":   { "type": "string", "title": "默认城市", "default": "北京", "maxLength": 20 },
    "count":  { "type": "integer", "title": "条数", "default": 3, "minimum": 1, "maximum": 10 },
    "loud":   { "type": "boolean", "title": "大声一点", "default": false },
    "mode":   { "type": "string", "title": "模式", "enum": ["简短", "详细"], "default": "简短" },
    "feeds":  { "type": "array", "title": "订阅地址", "items": { "type": "string" }, "default": [] },
    "token":  { "type": "string", "title": "API Key", "secret": true }
  }
}
```

- 插件页根据这个自动生成表单，保存时校验类型、范围、必填、`enum`。
- `secret: true` 的值加密存在数据库里，页面上只显示「已设置」，日志里不会出现。
- 插件里读 `p.settings["city"]`。用户改了设置会收到通知，不用重启：

```python
@p.on_settings
def changed(settings):
    p.log(f"新的城市：{settings.get('city')}")
```

### 4.8 自定义页面

插件文件夹里放 `web/index.html`，插件详情会出现「打开插件页面」，地址是 `/plugins/<id>/`。

- 页面在沙盒 iframe 里打开（`Content-Security-Policy: sandbox allow-scripts allow-forms`），读不到控制台的 Cookie 和页面内容。
- 页面里请求 `api/xxx`（相对路径）会转给插件：

```python
@p.web
def web(method, path, query, body):
    if path == "/stats":
        return {"count": p.kv_get("count", 0)}          # 返回对象就是 JSON
    return {"status": 404, "body": "没有这个页面"}
```

- 返回字符串是纯文本；返回 `{"status": ..., "body": ..., "contentType": ...}` 可以完全控制响应。每个请求最多 15 秒。

### 4.9 存储、记忆、大模型、日志

```python
p.kv_set("count", 3)                 # 值可以是任意 JSON
p.kv_get("count", 0)
p.kv_delete("count")
p.kv_list("seen:")                   # 按前缀列出键

p.recall("group:123456")             # 读记忆：self、diary、group:<群号>、user:<QQ>（memory.read）
p.remember("user:10001", "喜欢猫")    # 记一条（memory.write）

r = p.llm(prompt="用一句话总结：……", max_tokens=200)   # llm 权限
r["text"]

p.log("出错了", "warn")               # 插件日志：debug / info / warn / error
p.notify_web("RSS 有 3 篇新文章")     # 控制台右上角弹通知
```

- kv 每个值最多 1 MB，每个插件合计 10 MB。`kv_get` + `kv_set` **不是原子操作**，多个线程同时改同一个键要自己加锁。
- 插件的 `print` 和报错会进插件日志；每个插件每秒最多 50 行，多的合并成一行「省略了 N 行」。

### 4.10 主动发消息

```python
p.send(group_id="123456", text="定时提醒")        # qq.send，群要在「允许发消息的群」里勾上
p.send(user_id="10001", text="私聊")              # qq.private
p.send(group_id="123456", image="https://example.com/a.png")   # 图片：http(s) 地址或 base64://
p.history(group_id="123456", count=20)            # qq.read，最多 100 条
p.groups()                                        # [{"groupId": "...", "name": "..."}]
p.members("123456")                               # qq.read
```

- 主动发的消息和她自己说的话一样过内容审核。
- 频率限制：每个插件每分钟 10 条、每天 100 条，超了返回错误码 `-32002`。
- `ctx.reply` 每个触发最多回 5 次，触发后 10 分钟内有效。

### 4.x 直接调协议端接口（`qq.api`）

`qq.send` 只能发文字和图片。要发**语音、AI 语音、戳一戳、群文件**这些，用 `qq/call` 转发到协议端：

```python
p.qq("send_group_ai_record", {"group_id": 123456, "character": "小鲸鱼", "text": "你好呀"})
p.qq("send_group_msg", {"group_id": 123456, "message": [{"type": "record", "data": {"file": "https://example.com/a.amr"}}]})
```

- 可调接口清单：控制台「Agent › QQ 接口」里那份（协议端自己声明，现在是 199 个）
- **锁死的接口一律拒绝**（能拿凭据的、能让机器人下线的、内部调试的、流式的），会返回原因
- 走的是接口开关：某个接口你在控制台关掉了，插件也调不到
- **不做内容审核**（原始接口不一定是文本），发什么由插件自己负责
- 频率限制沿用插件那套（每分钟 10 条、每天 100 条）

## 5. Python SDK 参考

`from feiyu_plugin import Plugin, Context, RpcError`，只用标准库，Python 3.9 以上。

| 装饰器 | 说明 |
|---|---|
| `@p.command(name)` | 命令，参数 `ctx`。返回 `False` 交给她 |
| `@p.on(event)` | 事件，参数 `ctx`。`"*"` 收所有订阅的事件 |
| `@p.intercept` | 拦截，返回 `"pass"`、`"drop"`、`"hide"`、`("rewrite", 新文字)` 或新文字 |
| `@p.tool(name, description, properties, required=None, mind=False, timeout=None)` | 工具。参数按名字传进函数；函数只有一个 `args` 参数时传整个字典 |
| `@p.schedule(id)` | 定时任务 |
| `@p.prompt` | 提示词补充，参数 `(session, people)` |
| `@p.filter` | 出站过滤，参数 `(session, text)` |
| `@p.web` | 自定义页面接口，参数 `(method, path, query, body)` |
| `@p.on_init` / `@p.on_settings` / `@p.on_shutdown` | 启动完成 / 设置改了 / 退出前 |

| 属性 | 说明 |
|---|---|
| `p.settings` | 当前设置（字典） |
| `p.permissions` | 实际拿到的权限 |
| `p.plugin_id`、`p.data_dir`、`p.host_version`、`p.prefix` | 插件 id、数据目录、主程序版本、命令前缀 |

调宿主的方法出错时抛 `RpcError`，有 `code` 和 `message`。处理函数在线程池里跑（默认 16 个线程），慢的处理不会卡住其他调用。

## 6. Node SDK 参考

Node 18 以上。写法和 Python 一样，函数用回调传：

```js
const { Plugin } = require('feiyu_plugin');
const p = new Plugin();

p.command('掷骰子', ctx => ctx.reply(`掷出了 ${1 + Math.floor(Math.random() * 6)}`));
p.tool('add', '两数相加', { a: { type: 'integer' }, b: { type: 'integer' } }, args => String(args.a + args.b));
p.on('message.group', async ctx => { await p.kvSet('last', ctx.text); });

p.run();
```

清单里 `"run": { "command": "node", "args": ["main.js"] }`。方法名是驼峰：`kvGet`、`kvSet`、`kvDelete`、`kvList`、`notifyWeb`、`toolsChanged`、`onInit`、`onSettings`、`onShutdown`；`send`、`history`、`llm` 接收对象参数，比如 `p.send({ groupId, text })`。

插件文件夹里没有 `package.json` 时，宿主启动前会自动建一个（沙盒里 Node 往上找 `package.json` 会碰到没权限的目录）。

## 7. 协议（不用 SDK 时）

- 传输：插件的标准输入输出，每行一条 JSON-RPC 2.0 消息，UTF-8，一行最长 10 MB。
- 标准输出只能写协议消息，日志写标准错误（会进插件日志）。
- 两边都可以发请求（带 `id`）和通知（不带 `id`）。

### 宿主 → 插件

| 方法 | 类型 | 参数 | 期望的返回 |
|---|---|---|---|
| `initialize` | 请求，15 秒 | `hostVersion`、`pluginId`、`settings`、`dataDir`、`prefix`、`permissions`、`sandbox` | `{"tools": [...]}`（可选） |
| `command/run` | 请求，5 秒 | 消息字段 + `name`、`word`、`args`、`argv`、`ctx` | `{"handled": true/false}` |
| `event` | 拦截时是请求（2 秒），旁听时是通知 | `type` + 消息或通知字段 + `ctx` | 拦截时 `{"action": "pass" / "drop" / "hide" / "rewrite", "text": "..."}` |
| `tool/call` | 请求，按工具超时 | `name`、`arguments`、`session` | `{"content": [{"type": "text", "text": "..."}], "isError": false}` |
| `tools/list` | 请求 | | `{"tools": [...]}` |
| `prompt/contribute` | 请求，500 毫秒 | `session`、`people` | `{"text": "..."}` |
| `filter/outgoing` | 请求，2 秒 | `session`、`text` | 同拦截 |
| `schedule/fire` | 通知 | `id` | |
| `settings/changed` | 通知 | `settings` | |
| `web/request` | 请求，15 秒 | `method`、`path`、`query`、`body` | `{"status": 200, "body": "...", "contentType": "..."}` |
| `shutdown` | 通知 | | 收到后尽快退出，3 秒后强制结束 |

消息字段：`type`、`session`、`groupId`、`userId`、`sender`、`owner`、`text`、`attachments`、`mentionedMe`、`messageId`、`time`、`backfilled`。通知事件的字段：`groupId`、`userId`、`operatorId`、`targetId`、`messageId`、`subType`、`session`、`time`。

### 插件 → 宿主

| 方法 | 权限 | 参数 | 返回 |
|---|---|---|---|
| `qq/reply` | `qq.reply` | `ctx`、`text`、`image` | `{"ok": true, "text": "实际发出的话"}` |
| `qq/send` | `qq.send` / `qq.private` | `groupId` 或 `userId`、`text`、`image` | 同上 |
| `qq/history` | `qq.read` / `qq.private` | `groupId` 或 `userId`、`count` | 消息数组 |
| `qq/groups` | `qq.send` 或 `qq.read` | | `[{"groupId", "name"}]` |
| `qq/members` | `qq.read` | `groupId` | `[{"userId", "nickname"}]` |
| `qq/call` | `qq.api` | `action`、`params` | `{"ok": true, "data": {...}}` |
| `memory/recall` | `memory.read` | `about` | 记忆数组 |
| `memory/add` | `memory.write` | `about`、`text` | |
| `llm/chat` | `llm` | `prompt` 或 `messages`、`system`、`maxTokens` | `{"text", "promptTokens", "completionTokens"}` |
| `kv/get` | | `key` | `{"value": ...}` |
| `kv/set` | | `key`、`value` | `{"ok": true}` |
| `kv/delete` | | `key` | `{"ok": true/false}` |
| `kv/list` | | `prefix` | 键数组 |
| `log` | | `level`、`text` | 通知即可 |
| `notify` | | `text`（200 字以内） | |
| `tools/changed` | | | 通知，宿主随后调 `tools/list` |

错误码：`-32700` 解析失败、`-32600` 请求不合法、`-32601` 没有这个方法、`-32602` 参数不对、`-32000` 执行失败、`-32001` 没有权限、`-32002` 超过频率或存储上限。

## 8. 运行环境

- **沙盒**：默认开。Windows 上每个插件一个 AppContainer，Linux 用 bubblewrap，macOS 用 sandbox-exec。能读插件文件夹和 SDK，能读写自己的数据目录；读不到你的文档、桌面、其他插件的数据。没有 `network` 权限时断网；有也连不了本机，Windows 上连局域网也不行。Linux 上沙盒联网要装 passt，没装时插件会断网启动并在日志里说明。
- **资源**：内存 512 MB、CPU 50%、最多 16 个进程，关掉沙盒时 1 GB、80%、32 个。Linux 上的上限靠 systemd，没有 systemd 时和 macOS 一样只降优先级；关掉沙盒时 Linux 和 macOS 不限。主程序退出时插件进程一起结束。
- **Python**：Windows 上找 `python`，Linux 和 macOS 先找 `python3`。
- **环境变量**：`FEIYU_PLUGIN_ID`、`FEIYU_DATA_DIR`、`FEIYU_HOST_VERSION`、`FEIYU_WORKSPACE`（有 `files` 权限时）；`PYTHONPATH` / `NODE_PATH` 指向 SDK。
- **崩溃**：进程退出会自动重启（状态「崩溃了，等待重启」），间隔 1 秒起翻倍、最多 5 分钟；10 分钟内崩溃 5 次就停下来（状态「已自动停用」），插件页显示最后几行报错。改好后重新打开开关。
- **关沙盒**：插件详情里可以关掉，只对你完全信任的插件这么做（比如要调本机服务）。

## 9. 调试

1. **开发模式**（「插件 › 设置」）：改了插件文件夹里的文件，5 秒内自动重新加载。`__pycache__`、`.git`、`node_modules`、`.venv` 的变化不算。
2. **插件日志**：插件详情 › 日志。`print`、报错堆栈、`p.log` 都在这里；越权调用、超时、崩溃原因也在这里。
3. **立刻执行定时任务**：插件详情 › 定时任务 › 立刻执行。
4. **主程序日志**：控制台「日志」页里搜 `plugins:`。
5. **单独跑**：`python main.py` 后手动往标准输入贴 JSON，比如

   ```
   {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"settings":{}}}
   {"jsonrpc":"2.0","id":2,"method":"command/run","params":{"name":"掷骰子","ctx":"x","sender":"我"}}
   ```

   能看到插件回的每一行（`qq/reply` 请求会等宿主回应，单独跑时会超时，正常）。

常见问题：

| 现象 | 原因 |
|---|---|
| 状态一直是「等待同意权限」 | 清单里加了新权限，打开开关重新同意 |
| 「清单有问题」 | 看列出的字段；最常见的是 id 和文件夹名不一致 |
| 启动后立刻崩溃，日志里 `ModuleNotFoundError` | 用了第三方库。沙盒里没有你的用户目录，第三方库要放进插件文件夹（比如 `pip install -t libs`，再 `sys.path.insert`） |
| 联网报错 | 没声明 `network`，或者在连本机 / 局域网地址 |
| Node 插件 `EPERM` | 升级到 Node 18+；宿主已经带了 `--preserve-symlinks` |
| 命令没反应 | 命令名和别的插件冲突（插件页有提示）；或者 `scope` 不包含这个场景 |

## 10. 打包、安装、升级、卸载

- **打包**：把插件文件夹压成 zip。压缩包里可以直接是 `plugin.json`，也可以套一层文件夹。不要带 `__pycache__`、`node_modules` 里没用的东西。
- **安装**：「插件 › 已安装 › 安装插件」，三种方式：上传 zip、填 Git 仓库地址、填 zip 的网址（只支持 http/https）。先显示清单和要的权限，确认后才落盘启用。
- **安全限制**：压缩包里有 `../`、绝对路径、符号链接、解压后超过 100 MB 或 2000 个文件的会被拒绝；下载最大 50 MB。
- **升级**：装同一个 id 的新版本就是升级，设置、kv、数据目录都保留；版本号变小会提示降级；多要了权限会重新问。
- **卸载**：插件详情 › 卸载，可以选是否同时删掉它的数据和设置。

## 11. MCP 服务器

「插件 › MCP 服务 › 添加服务」：

- **本地（stdio）**：填命令和参数，比如 `npx -y @modelcontextprotocol/server-filesystem D:\notes`。默认在沙盒里跑并且断网，可以分别打开「联网」或关掉沙盒。
- **远程（Streamable HTTP）**：填地址和请求头（比如 `Authorization`，标成密钥后加密存储）。
- 支持协议版本 2025-06-18、2025-03-26、2024-11-05。服务器的工具名在她那里是 `mcp__<服务名>__<工具名>`；Agent 里默认可用，QQ 聊天和内心活动要分别打开。
- 连不上、启动后立刻退出、协议版本不兼容时，列表里会显示原因。

## 12. 技能包

技能是她学会的做法，不跑代码。「Agent › 记忆 › 技能」里点「导入」，选：

- 一个 `SKILL.md`：

  ```markdown
  ---
  name: 煮泡面
  description: 有人问怎么煮泡面时
  ---

  1. 水开后下面饼
  2. 煮三分钟
  ```

  没有 `name` 时用第一个 `# 标题`，再没有就用文件名。

- 一个 zip：里面所有叫 `SKILL.md` 的文件都会导入（比如 `skills/煮泡面/SKILL.md`），没写名字的用所在文件夹名。

同名的技能会先问你：覆盖，还是只导入新的。正文超过 3000 字的只保留前面的部分，导入后会提示。导入的技能和她自己学会的一样，聊天时用得上就会照着做；也可以在同一页修改、删除、下载。
